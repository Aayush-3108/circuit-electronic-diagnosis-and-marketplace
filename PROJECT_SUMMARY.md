# Circuit Project: Core Concepts, Algorithms & Materials

This document provides a concise overview of the fundamental components, algorithms, and terminologies used in the Circuit Electronics Diagnosis & Marketplace project.

## 1. Materials Used (Technology Stack)

### Frontend
*   **React (Vite)**: The user interface is a Single Page Application (SPA) built with React. State is managed locally without a complex router.
*   **Tailwind CSS**: Used for rapid UI styling, combined with native CSS variables for a comprehensive design system (light/dark modes).
*   **Firebase SDK**: Handles user authentication and ID token generation.
*   **Cloudinary**: An external CDN used for hosting images uploaded to the marketplace.

### Backend
*   **FastAPI**: A modern, fast Python web framework. It handles all REST API requests from the frontend.
*   **Uvicorn**: The ASGI server that runs the FastAPI application.
*   **Pydantic**: Used extensively for data validation (ensuring the frontend sends correct data types before the backend processes them).

### Machine Learning & Data
*   **scikit-learn**: Used for Random Forest (classification), Isolation Forest (fraud detection), and One-Hot Encoding (data preparation).
*   **XGBoost & LightGBM**: Advanced gradient boosting libraries used for numerical regression (predicting prices).
*   **Ultralytics YOLOv8**: The state-of-the-art computer vision library used for analyzing images.
*   **SQLite / Firestore**: SQLite is used for local database storage (zero-configuration fallback), while Firestore is the production cloud database.

## 2. Core Algorithms & Models

### A. YOLOv8 (Computer Vision)
*   **What it is**: You Only Look Once version 8 is a real-time object detection model.
*   **How it's implemented**: When a user uploads a photo of a device, YOLO scans the image and draws "bounding boxes" around detected damage (e.g., screen crack, scratches). It outputs the *type* of damage and a *confidence score*.

### B. Random Forest Classifier (The Decision Engine)
*   **What it is**: An algorithm that builds multiple "decision trees" and takes a majority vote to classify data.
*   **How it's implemented**: It takes the damage data from YOLO plus the device specs (age, original price, battery health) and decides the best action: **Sell, Repair, Recycle, or Upgrade**. 

### C. XGBoost & LightGBM (Financial Estimators)
*   **What they are**: Gradient boosting models that predict continuous numerical values (regression).
*   **How they're implemented**: XGBoost predicts the **estimated repair cost**, while LightGBM predicts the **estimated resale value**. They are trained on a synthetic dataset of 8,000 device records to understand price depreciation.

### D. Isolation Forest (Fraud Detection)
*   **What it is**: An anomaly detection algorithm that isolates outliers rather than profiling normal data points.
*   **How it's implemented**: When a user creates a marketplace listing, this model evaluates the price, condition, and device type. If the price is abnormally high or low compared to market standards, it flags the listing as potentially fraudulent.

### E. Haversine Formula (Repair Shop Finder)
*   **What it is**: A mathematical equation to calculate the great-circle distance between two points on a sphere given their longitudes and latitudes.
*   **How it's implemented**: Used in the backend to calculate exactly how far a user is from repair shops fetched via the OpenStreetMap API.

### F. Part Matching (Compatibility Engine)
*   **What it is**: A rule-based lookup algorithm.
*   **How it's implemented**: Uses a hardcoded dictionary (`COMPATIBILITY_RULES`). If you have a broken iPhone 12, the algorithm knows an iPhone 12 Pro screen might be compatible. It filters the active marketplace database to find donor devices for the user's specific repair needs.

## 3. Major Terminologies

*   **Inference**: The process of running live data through a trained Machine Learning model to get a prediction (e.g., when the backend asks YOLO what damage is in a photo).
*   **One-Hot Encoding (OHE)**: Converting text categories (like "phone" or "laptop") into binary numbers (1s and 0s) so that the Machine Learning models (Random Forest, XGBoost) can understand them mathematically.
*   **Fallback Chain / Graceful Degradation**: A software design pattern used heavily here. If a primary system fails, a backup takes over. For example, if the Local YOLO model is missing, it falls back to a Roboflow Cloud API, and if that fails, it falls back to a Mock (simulated) result.
*   **JWT (JSON Web Token)**: A secure string generated by Firebase when a user logs in. The frontend sends this to the backend to prove the user is authenticated.
*   **SPA (Single Page Application)**: The React frontend never actually loads a new HTML page. Instead, it just hides and shows different components (like the Dashboard or Analyze Form) instantly based on internal state.
*   **P2P Marketplace**: Peer-to-Peer. Users sell directly to other users, rather than buying from a central store.

## 4. How Everything Connects (In Short)

1.  **Input**: The user interacts with the **React** frontend to upload a photo and enter device specs.
2.  **Transport**: The frontend sends this data securely via an API call to the **FastAPI** backend.
3.  **Vision**: The backend hands the photo to **YOLOv8** to identify physical damage.
4.  **Decision**: The damage results + user specs are converted into numbers (One-Hot Encoded) and fed into the **Random Forest, XGBoost, and LightGBM** models.
5.  **Output**: The models return a recommendation (e.g., "Repair") and cost estimates.
6.  **Marketplace Integration**: If "Repair" is recommended, the backend searches the **SQLite/Firestore** database using the **Part Matching** rules to find compatible parts being sold by other users.
7.  **Display**: The final packaged results are sent back to the **React** frontend and displayed beautifully to the user.
